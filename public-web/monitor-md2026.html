Lesehinweis: „Vorher" ist eine fixe Baseline aus — echte Sitzungen der alten Store-Version. „v6" ist ein rollierendes 72-Stunden-Fenster. Der Plattform-Filter wirkt auf die v6-Balken; „vorher" bleibt Gesamt (Alt-Sitzungen tragen keine Plattform-Info). Eine Sitzung startet automatisch beim App-Öffnen (mit Einwilligung).

Grün = ab Store-Release 6.0 (11.07.). Letzter Tag ist unvollständig.

Kernfragen

Onboarding-Funnel

Neu-Installs = im 72h-Fenster angelegte User mit 6.0-Session. „Begonnen" = mindestens eine bewusste Interaktion im Flow (der Start-Screen schreibt nichts — in alter wie neuer Version identisch gemessen). Vorher = fixes 5.x-Fenster 04.–06.07.; „aktiv geworden" vorher = Stichprobe (n=500, ±4pp). Der Plattform-Filter wirkt hier nicht. Caveat: „Neu-Installs" enthält aktuell auch Bestands-User, die das 5.x→6.0-Update neu anonymisiert hat (Session-Verlust der Migration) — sie überspringen das Onboarding und drücken die Start-Quote nach unten.

Einkauf & Abschluss

v6-Sitzungen sind jung (72h-Fenster), Alt-Sitzungen hatten Tage zu reifen — v6-Werte sind eher Untergrenzen.

Definitionen: „Ohne Aktion geschlossen" = kein Produkt angesehen, kein Filter geändert, kein Scan, keine Suche, kein Freitext. Sitzungen pro Journey-ID dedupliziert. Onboarding/Demografie/Markt werden pro User direkt vom Profil (users-Doc) der im Fenster aktiven User gemessen — nicht pro Sitzung (der Sitzungs-Schnappschuss entsteht vor dem Onboarding und unterzählt strukturell); erfasst erst seit 6.0. Sitzungsdauer wird nicht verglichen (Alt-Daten dafür defekt).
